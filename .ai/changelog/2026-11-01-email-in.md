# Email-in

- Date: 2026-11-01
- Area: api, web, shared, docs
- Spec: §7, ADR 0012

## Summary

Members can create a request by emailing a request type's address. Ordler reads one IMAP
mailbox every minute, submits the request as the sender through the normal request service,
links attachments, and replies with a confirmation or with the portal link when the email
cannot become a request.

## Changes

- New dependencies: `imapflow` 2.4.2 and `mailparser` 3.9.39 (MIT); ADR 0012.
- `apps/api/drizzle/0027_email_in.sql` — `inbox_settings`, `inbound_emails` (unique
  Message-ID), `request_types.email_address` (unique).
- `apps/api/src/email-in/` — IMAP connector, `EmailInService` (settings, poll, receive,
  replies, log, worker runner), `/api/admin/mail/inbox` endpoints behind `mail.manage`.
- Request types take an optional `emailAddress`; leaving it out of an update keeps it, and a
  taken address answers `409 email_address_taken`.
- Outgoing mail can carry `In-Reply-To` and extra headers (`Auto-Submitted`).
- Two new editable templates: `email_in_received`, `email_in_rejected`.
- Web: email address in the request type editor; Admin → Mail → Incoming mail with mailbox
  settings, "Check now", last error and recent messages; strings in all four locales.

## Tests

- HTTP with an in-memory mailbox: request created with attachment and threaded confirmation;
  one request per Message-ID; strangers, unknown addresses and robots ignored without reply;
  Delivered-To routing; required form fields declined with portal link; member without
  `request.create` declined; deactivated member ignored; connection error stored; password
  never returned or audited; 403 without `mail.manage`; address uniqueness and keep-on-omit.
- Web: mailbox form, message log, check-now error; request type editor sends the address.

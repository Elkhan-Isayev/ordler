# Slack app

- Date: 2026-11-01
- Area: api, web, shared, docs
- Spec: §7.1 (level 2), ADR 0013

## Summary

The Ordler Slack app: a manifest for the company's own Slack app, Socket Mode (or HTTPS)
connection, personal DMs of Inbox events, a public-channel picker for subscriptions, link
unfurls and "Create issue" / "Create request" message shortcuts, all acting as the linked
Ordler member.

## Changes

- `apps/api/drizzle/0028_slack_app.sql` — `slack_app` (sealed secrets), `slack_links`,
  `chat_subscriptions.channel_id/channel_name`; the webhook target becomes optional.
- `apps/api/src/slack/` — Web API client, Socket Mode client (built-in WebSocket), runtime
  that follows settings changes, `SlackAppService` (settings, manifest, Sign in with Slack
  linking, DMs, channels, unfurls, shortcuts and modals), HTTPS routes with v0 signature
  checks, controllers `admin/slack-app` and `me/slack`.
- Notifications send DMs through a lazy `DirectMessenger`; channel subscriptions post through
  the bot when they name a channel.
- New error codes `slack_not_configured`, `slack_rejected`; Slack strings in all four locales.
- Web: Admin → Integrations → Slack app panel (steps, manifest, tokens, mode, status),
  channel picker for subscriptions, Settings → Slack (link, DMs toggle, unlink).

## Tests

- HTTP with a fake Slack: settings and workspace from `auth.test`, secrets never returned or
  audited, bad token and missing app token refused, manifest, admin-only; linking allowed and
  refused (other workspace, forged state, wrong nonce, unconfigured); DMs on and off; channel
  subscription posting through the bot; unfurl for a linked member only; create issue from a
  message; nothing for unlinked users; HTTPS signature, stale timestamp and mode checks.
- Socket Mode client: acks with handler results, reconnects on `disconnect`, backs off.
- Web: Slack app panel, channel picker, Settings → Slack.

## Notes

Not exercised against a real Slack workspace in this change; the fake covers the documented
API shapes.

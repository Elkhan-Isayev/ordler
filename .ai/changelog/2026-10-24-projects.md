# Projects with milestones and status updates

- Date: 2026-10-24
- Area: api, web, shared
- Spec: §5.2 Projects, §14 Phase 2

## Summary

Projects group work across teams: name, description, status, lead, members, teams, start and
target dates, milestones, status updates with health (on track / at risk / off track), and
progress as completed over total issues. Issues join a project or one of its milestones from
the issue page, the new-issue dialog or the right-click menu, and lists filter by project.

## Changes

- `apps/api/drizzle/0017_projects.sql` — `projects`, `project_teams`, `project_members`,
  `project_milestones`, `project_updates`, `issues.project_id` / `milestone_id` (additive).
- `apps/api/src/projects/` — `ProjectService` and routes: visible through any readable team,
  created with `project.manage` on every chosen team, edited by the lead or project managers,
  updates posted by members too; archiving and removing a team detach issues, never delete
  them; audited.
- Issues: project/milestone validation (the project must include the team; a milestone implies
  its project; changing project drops a foreign milestone), history entries;
  `TeamView.projects`; `GET /api/teams` (readable teams for pickers); MCP `create_issue`
  accepts `project`.
- Web: `/projects`, `/teams/KEY/projects`, project page (properties, description, milestones,
  status updates, issues), project and milestone pickers, project filter; date chips take a
  field-specific placeholder; i18n en/ru/de/az.
